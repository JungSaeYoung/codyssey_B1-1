# 쉘 스크립트 처음부터 — `src/` 전체 한 줄씩 읽기

이 문서는 `src/` 아래 **11 개 쉘 스크립트가 왜 그렇게 쓰였는지** 를 처음 보는 사람 기준으로 설명한다. 11 개 모두 한 가지씩만 단단하게 하는 작은 스크립트라 길어 보여도 패턴은 몇 개 안 된다.

## 0. 전체 구조 한눈에

```
src/
├── 00_run_all.sh                ← wrapper : 01~07 을 순서대로 실행
│
├── 01_ssh_hardening.sh          ┐
├── 02_firewall_allowlist.sh     │
├── 03_users_and_groups.sh       │ setup 7 단계 (1회성)
├── 04_directories_and_acl.sh    │ sudo 가 가능한 관리자 계정에서 실행
├── 05_env_and_keyfile.sh        │
├── 06_deploy_app_and_scripts.sh │
├── 07_cron_schedule.sh          ┘
│
├── monitor.sh                   ┐
├── report.sh                    │ 운영 (반복 실행)
└── archive_logs.sh              ┘ agent-admin 계정 / cron 으로 동작
```

**두 갈래로 나뉜다.**

- **setup 7 단계 (`01_…` ~ `07_…`)** — 머신을 처음 셋업할 때 한 번만 돌린다. 각 단계는 **하나의 주제**(SSH, 방화벽, 계정, …) 만 다룬다.
- **운영 3 종 (`monitor.sh`, `report.sh`, `archive_logs.sh`)** — setup 이 끝난 뒤 cron 또는 손으로 계속 호출하는 스크립트. agent-app 의 상태를 측정·집계·보관한다.

`00_run_all.sh` 는 setup 7 단계를 **순서대로** 부르는 wrapper. "한 번에" 가 필요할 때만 쓰고, 학습 목적이라면 01~07 을 손으로 한 줄씩 돌려 출력을 확인하는 게 좋다.

## 1. 쉘 스크립트가 뭐냐 — 1 분 요약

쉘 스크립트는 **터미널에 한 줄씩 치던 명령어를 파일에 모아둔 것**이다. 그뿐이다.

```bash
echo "hello"
ls /tmp
date
```

이걸 `hello.sh` 라는 파일에 저장한 뒤 `bash hello.sh` 라고 실행하면, 위 세 줄을 순서대로 터미널에 친 것과 똑같이 동작한다. 변수·반복문·조건문은 그 위에 얹는 편의 기능.

## 1.5 처음 만나는 단어들 — 한 페이지 사전

스크립트를 한 줄도 읽기 전에 알아두면 좋은 단어들. 뒤에서 자꾸 나온다.

| 단어 | 한 줄 설명 |
|------|-----------|
| **종료 코드 (exit code)** | 모든 명령은 끝날 때 0~255 의 숫자를 반환한다[^1]. **0 = 성공**, 그 외 = 실패. 사람 직관과 반대라 처음에 헷갈린다. `echo $?` 로 직전 명령의 종료 코드를 볼 수 있다. |
| **표준 출력 (stdout, 1번)** | 명령이 "정상 결과" 를 흘려보내는 통로. `echo hello` 의 `hello` 가 여기로. |
| **표준 에러 (stderr, 2번)** | 명령이 "에러 메시지" 를 흘려보내는 별개 통로. 화면에는 같이 섞여 보이지만 내부적으론 따로다. |
| **표준 입력 (stdin, 0번)** | 명령이 "읽어 들이는" 통로. 키보드 입력이나 파이프로 들어오는 값. |
| **PATH** | "명령 이름만 쳤을 때 어디서 찾을지" 알려주는 환경변수. `ls` 만 쳤는데 동작하는 건 PATH 에 `/usr/bin` 이 들어 있어 `/usr/bin/ls` 를 찾아주기 때문. |
| **sudo** | "관리자(root) 권한으로 이 명령 한 줄만 실행" 시켜주는 도우미. 시스템 파일을 건드릴 때 필요. |
| **셸 (shell)** | 우리가 명령을 입력하면 해석해서 실행해 주는 프로그램. bash / zsh / sh 등이 있고, 이 프로젝트는 전부 bash 기준. |
| **환경변수** | 셸과 자식 프로세스가 공유하는 "전역 변수". `export NAME=값` 으로 만들고, `$NAME` 또는 `${NAME}` 으로 읽는다. |
| **프로세스 / PID** | 실행 중인 프로그램 한 인스턴스 = 프로세스. 각각 고유한 번호(PID) 가 붙는다. `ps`, `pgrep` 으로 확인. |
| **데몬 (daemon)** | 백그라운드에서 계속 떠 있는 서비스 프로세스. `sshd`, `ufw`, `cron` 같이 `d` 로 끝나는 이름이 많다. |
| **cron** | "지정한 시각마다 명령을 자동 실행" 해 주는 시스템. `crontab` 명령으로 등록. |

## 1.6 파이프 · 리다이렉트 — "출력의 흐름" 한 번에 정리

이 문서 곳곳에 `|`, `>`, `>>`, `2>&1`, `>/dev/null` 같은 기호가 쉴 새 없이 나온다. 이건 전부 **명령의 출력을 어디로 보낼지** 정하는 문법이다. 한 번 정리하면 90% 가 읽힌다.

### 파이프 `|` — 앞 명령의 출력을 뒤 명령의 입력으로

```bash
ls /etc | grep conf | wc -l
```

읽는 순서: `ls /etc` (목록) → `grep conf` (그 중 conf 들어간 줄) → `wc -l` (줄 수 세기). **세 명령이 동시에 떠서 데이터가 흘러간다.**

### 리다이렉트 — 출력을 화면 대신 파일로

| 표기 | 의미 |
|------|------|
| `cmd > file` | stdout 을 file 에 **덮어쓰기** (기존 내용 날아감) |
| `cmd >> file` | stdout 을 file 에 **이어쓰기** |
| `cmd < file` | file 을 stdin 으로 넣어줌 |
| `cmd 2> file` | **stderr** 만 file 로 |
| `cmd > file 2>&1` | stdout 도 file 로 보내고, 그 다음 **stderr 를 stdout 과 같은 곳으로**[^2] → 결국 둘 다 file 에 |
| `cmd &> file` | (bash 전용) 위와 동일, 짧은 표기 |
| `cmd >/dev/null` | stdout 을 **버림** (`/dev/null` 은 "쓰면 사라지는 가짜 파일") |
| `cmd 2>/dev/null` | stderr 만 버림 (에러 메시지 묻기) |
| `cmd >/dev/null 2>&1` | 출력·에러 둘 다 버림 (조용히 실행하고 종료코드만 보고 싶을 때) |

**왜 `>/dev/null 2>&1` 같은 게 자주 나오나** — `if command -v ss >/dev/null 2>&1; then …` 처럼 "이 명령이 존재하는지" 만 보고 싶을 때, 출력은 화면을 더럽히니 다 버리고 **종료 코드만** 쓰려는 패턴이다.

> 💡 `2>&1` 의 순서가 중요. `cmd 2>&1 > file` 은 의도와 다르게 동작한다 (stderr 는 여전히 화면으로 감)[^3]. **항상 `> file 2>&1` 순서**로 외워두자.

## 2. 모든 스크립트의 공통 머리

`src/` 모든 파일은 두세 줄로 시작한다.

```bash
#!/usr/bin/env bash
set -eu     # setup 스크립트(01~07, 00_run_all)
set -u      # 운영 스크립트(monitor.sh / report.sh / archive_logs.sh)
```

### `#!/usr/bin/env bash` (셔뱅, shebang)

- 파일 **첫 줄**에 `#!` 로 시작하는 건 OS 한테 "이 파일을 어떤 프로그램으로 실행해야 하는지" 알려주는 표지판.
- `/usr/bin/env bash` 는 "지금 PATH 에 잡힌 bash 를 실행해줘" 라는 뜻. `#!/bin/bash` 도 되지만 env 가 시스템 간 호환성이 좋아 관례.
- 이 줄이 있고 파일에 실행 권한(`chmod +x`)이 있으면 `./monitor.sh` 만으로 실행된다.

### `set -e` / `set -u` / `set -o pipefail`

bash 의 "안전 모드" 옵션. setup 과 운영의 정책이 다르다.

| 옵션 | 의미 | 우리 코드 |
|------|------|-----------|
| `-e` | 명령이 **실패(0이 아닌 종료코드)** 하면 즉시 스크립트 종료 | setup 만 사용 |
| `-u` | **선언되지 않은 변수**를 쓰면 에러로 중단 | setup + 운영 모두 |
| `-o pipefail` | 파이프(`|`) 안에서 한 단계라도 실패하면 전체 실패로 봄 | (사용 안 함) |

왜 운영 쪽엔 `-e` 가 없냐 — `monitor.sh` 는 "자원 수집 명령 하나가 실패해도 다른 단계는 계속 진행" 해야 cron 출력이 끊기지 않는다. 반대로 setup 은 "어느 한 단계라도 실패하면 그대로 멈추는" 게 안전.

> 💡 함정 : `set -e` 가 켜져 있으면 `cmd || true` 처럼 명시적으로 "실패해도 OK" 를 표시해야 한다. 우리 setup 스크립트 곳곳에 `|| true` 가 보이는 이유.

## 3. setup 7 단계 — 각 단계가 하는 일

7 단계의 공통 패턴은 다음 3 가지다. 이것만 알면 어떤 setup 스크립트를 봐도 읽힌다.

1. **`step()` 헬퍼** — `step() { printf "  ▶ %s\n" "$*"; }`. 침묵 명령 직전에 무엇을 할지 한 줄 출력. `printf "▶ %s\n" "$*"` → `"$*"` 는 "함수에 넘어온 모든 인자를 한 문자열로 합친 것".
2. **있으면 skip / 없으면 설치** — `command -v ufw >/dev/null 2>&1` 같은 조건으로 멱등성(여러 번 돌려도 같은 결과)을 보장.
3. **마지막에 `── 검증 ──` 블록** — `id agent-admin`, `ufw status verbose` 같은 즉시 확인 명령을 모아 두어 학습자가 결과를 눈으로 확인.

### 3.1 `01_ssh_hardening.sh` — SSH 포트 변경 + Root 차단

핵심 한 줄:

```bash
sudo sed -i -E \
    -e 's/^#?Port .*/Port 20022/' \
    -e 's/^#?PermitRootLogin .*/PermitRootLogin no/' \
    /etc/ssh/sshd_config
```

- `sed -i` : in-place(파일을 그 자리에서) 수정.
- `-E` : 확장 정규식 사용 (`?`, `+` 같은 문법).
- `-e '명령'` : 여러 번 쓰면 여러 패턴을 한 번에 적용.
- `s/원본/대체/` 형식. `^#?Port .*` 는 "줄 처음에 `Port` 가 있고 (앞에 `#` 있어도 없어도) 그 뒤 아무거나" 를 잡는다. 주석 처리된 `#Port 22` 도, 평문 `Port 22` 도 둘 다 `Port 20022` 로 바뀌도록 한 트릭.

부가 단계:

```bash
sudo systemctl disable --now ssh.socket 2>/dev/null || true
sudo systemctl enable ssh
sudo systemctl restart ssh
```

Ubuntu 24.04 는 sshd 를 "필요할 때만 깨우는" `ssh.socket` 모드로 기본 동작한다. 이 상태에서 `sshd_config` 의 `Port` 를 바꿔도 socket 이 `:22` 만 듣고 있어 무력화될 수 있어, **socket 을 끄고 service 로 항상 켜둔다**.

### 3.2 `02_firewall_allowlist.sh` — UFW 화이트리스트

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 20022/tcp comment 'SSH'
sudo ufw allow 15034/tcp comment 'AGENT APP'
sudo ufw --force enable
sudo systemctl enable --now ufw
```

- `default deny incoming` : 들어오는 통신은 일단 전부 거부 → "허용한 것만 들어오게" (=화이트리스트).
- `default allow outgoing` : 나가는 통신은 허용 (운영 편의).
- `ufw allow PORT/PROTO comment '...'` : 예외 추가. `comment` 는 `ufw status verbose` 에 그대로 노출되어 운영 메모로 유용.
- `ufw --force enable` : "한 번 더 묻지 말고 그냥 켜라". 보통 첫 활성화 때 "SSH 끊길 수도 있다" 경고 + y/N 프롬프트가 뜨는데, 스크립트에선 입력 받을 수 없어 `--force` 가 필수.
- `systemctl enable --now ufw` : `ufw enable` 만으론 systemd unit 이 비활성으로 남는 환경(OrbStack 등) 이 있어 한 번 더 명시.

### 3.3 `03_users_and_groups.sh` — 계정 3종 / 그룹 2종

```bash
sudo groupadd -f agent-common
sudo groupadd -f agent-core

for u in agent-admin agent-dev agent-test; do
    if ! id "$u" >/dev/null 2>&1; then
        sudo useradd -m -s /bin/bash "$u"
    fi
done

sudo usermod -aG agent-common agent-admin agent-dev agent-test
sudo usermod -aG agent-core   agent-admin agent-dev   # test 제외
```

- `groupadd -f` : 이미 있어도 에러 안 내고 그냥 넘어감.
- `id "$u" >/dev/null 2>&1` : "그 계정이 존재하는지" 만 알고 출력은 버림. 멱등성 패턴.
- `useradd -m -s /bin/bash u` : `-m` = 홈 디렉토리 자동 생성, `-s /bin/bash` = 기본 셸 지정.
- `usermod -aG group user` : 사용자를 그룹에 **추가**. `-a` (append) 가 없으면 기존 보조 그룹이 다 날아가니[^4] 거의 항상 같이 쓴다.

> 💡 **`for u in A B C; do … done` 문법** (처음 등장)
>
> ```bash
> for 변수이름 in 값1 값2 값3; do
>     "$변수이름" 사용하는 명령들
> done
> ```
>
> 위 코드에선 `u` 가 차례로 `agent-admin`, `agent-dev`, `agent-test` 가 되며 안쪽 블록이 3번 실행된다. **세미콜론(`;`)** 은 줄바꿈 대신이고, `do … done` 이 반복 블록의 시작·끝.
>
> 변수 안에 공백·특수문자가 들어갈 수 있으니 안에서는 **항상 `"$u"` 처럼 큰따옴표로 감싼다** (§6 참고).

핵심 설계 — `agent-core` 에 `agent-test` 를 일부러 **제외**해서 "필요한 사람만 본다" (Need-to-Know) 원칙을 표현.

### 3.4 `04_directories_and_acl.sh` — 디렉토리 + 권한 + ACL

```bash
sudo chmod 750 "${AGENT_HOME}"
sudo chmod 770 "${AGENT_HOME}/upload_files"
sudo chmod 770 "${AGENT_HOME}/api_keys"
sudo chmod 770 "${LOG_DIR}"

sudo setfacl -m  g:agent-common:rwx "${AGENT_HOME}/upload_files"
sudo setfacl -dm g:agent-common:rwx "${AGENT_HOME}/upload_files"
```

#### POSIX 권한 숫자의 의미

```
chmod 750 dir
       │
       └── 7=owner(rwx) / 5=group(r-x) / 0=others(없음)
```

비트 매핑: `r=4 w=2 x=1`. 그 합. 디렉토리에선 `x` 가 "들어갈 수 있는 권한", `r` 이 "목록 보기".

#### `setfacl` — POSIX 권한의 한계를 보완

POSIX 표준 권한은 한 디렉토리에 owner / group / others **세 개**까지만 잡을 수 있다[^5]. "agent-core 에는 rwx, 그러나 agent-common 에는 r-x" 처럼 그룹을 둘 이상 다루려면 ACL(Access Control List) 이 필요.

- `setfacl -m g:GRP:rwx PATH` : 그룹 추가/수정.
- `setfacl -dm g:GRP:rwx PATH` : **default ACL**. 이 디렉토리 안에 **새로 만들어지는** 파일/하위 디렉토리에 자동 상속[^6].
  - 이게 빠지면 `monitor.sh` 가 `/var/log/agent-app/monitor.log` 를 처음 만들 때 정책에서 벗어난 권한이 잡혀, 다른 계정이 못 읽는 사태가 발생.

검증은 `getfacl PATH` — POSIX 와 ACL 을 모두 한 번에 출력해 준다.

### 3.5 `05_env_and_keyfile.sh` — 환경변수 + API 키

```bash
if ! sudo grep -q '^export AGENT_HOME=' "${AGENT_BASHRC}" 2>/dev/null; then
    sudo -u agent-admin tee -a "${AGENT_BASHRC}" >/dev/null <<'EOF'

# ----- Agent App ENV -----
export AGENT_HOME="/home/agent-admin/agent-app"
...
EOF
fi
```

- `if ! ... ; then ... fi` : 조건 앞에 `!` 로 부정. "이미 등록돼 있지 *않다면*" 에만 추가 → 여러 번 돌려도 줄이 중복되지 않음 (멱등).
- `sudo -u agent-admin tee -a FILE` : agent-admin 권한으로 파일 끝에 이어쓰기. `tee` 를 쓰는 이유는 `sudo` 가 리다이렉트(`>>`) 자체엔 작용 못 하기 때문 — `sudo >>file` 은 셸이 먼저 file 을 열어버려 권한 거부가 난다.
- `<<'EOF' … EOF` : **heredoc**. 시작 마커 `'EOF'` 를 작은따옴표로 감싼 이유 — 안의 `$AGENT_HOME` 같은 표현이 미리 치환되지 않고[^7] **문자 그대로** 파일에 기록되게. (agent-admin 셸이 열릴 때 비로소 풀리도록.)

API 키:

```bash
echo "agent_api_key_test" | sudo -u agent-admin tee "${KEY_PATH}" >/dev/null
sudo chown agent-admin:agent-core "${KEY_PATH}"
sudo chmod 640 "${KEY_PATH}"
```

- `640` = `rw- r-- ---` → owner 읽기/쓰기, group 읽기만, others 없음. 비밀이지만 같은 팀(`agent-core` = admin+dev) 은 검증할 수 있음.

### 3.6 `06_deploy_app_and_scripts.sh` — 바이너리 + 스크립트 배포

```bash
sudo install -m 0750 -o agent-dev -g agent-core \
    "${SOURCE_DIR}/monitor.sh"  "${AGENT_HOME}/bin/monitor.sh"
```

- `install` = `cp` 의 강화판. 한 명령으로 **복사 + 권한 모드[^8](`-m`) + 소유자(`-o`) + 그룹(`-g`)** 을 한 번에 지정. 따로따로 `cp` → `chmod` → `chown` 하는 것보다 안전(중간 상태가 없음).
- `0750` 의 앞자리 `0` 은 8진수 표기 명시. `chmod` 가 8진수 외엔 안 받으므로 사실상 같지만 관례.

CRLF 정리:

```bash
sudo dos2unix "${SOURCE_DIR}"/monitor.sh ... 2>&1 | sed 's/^/      /' || true
```

- Windows 에서 작성한 파일은 줄 끝이 `\r\n` 이라 bash 가 보이지 않는 `\r` 까지 명령 일부로 인식해 깨진다. `dos2unix` 로 LF 로 변환.
- `2>&1 | sed 's/^/      /'` : stderr 도 stdout 으로 합치고, 모든 줄 앞에 공백 6칸을 붙여 들여쓰기. 미관용.

시연용 사본:

```bash
sudo install -m 0750 -o agent-admin -g agent-admin \
    "${SOURCE_DIR}/report.sh" "/home/agent-admin/report.sh"
```

정식 위치(`$AGENT_HOME/bin/`) 외에도 `~/report.sh` 로 admin/dev 의 홈에 복사. 시연 중 `sudo -iu agent-dev` 직후 `~/report.sh` 한 줄로 즉시 통계를 볼 수 있게.

### 3.7 `07_cron_schedule.sh` — cron 등록

```bash
sudo -u agent-admin bash -c '
( crontab -l 2>/dev/null | grep -v "monitor.sh" | grep -v "archive_logs.sh" ;
  echo "* * * * * AGENT_HOME=... AGENT_PORT=15034 AGENT_LOG_DIR=... /home/agent-admin/agent-app/bin/monitor.sh >> ... 2>&1"
  echo "10 3 * * * /home/agent-admin/agent-app/bin/archive_logs.sh >> ... 2>&1"
) | crontab -
'
```

읽는 순서:

1. `sudo -u agent-admin bash -c '...'` — agent-admin 권한으로 한 덩어리 실행.
2. `crontab -l 2>/dev/null` — 현재 crontab 출력 (없으면 에러 → `2>/dev/null` 로 묻음).
3. `| grep -v "monitor.sh" | grep -v "archive_logs.sh"` — **monitor.sh / archive_logs.sh 가 들어간 줄을 제거**. 여러 번 돌려도 중복 등록 방지.
4. `; echo "..."` — 그 뒤에 새 줄 2 개를 이어 붙임. `(  ;   )` 의 괄호는 "이 안의 출력을 합쳐 하나의 스트림으로" 묶는 용도.
5. `| crontab -` — 그 합쳐진 결과를 crontab 의 표준입력으로 넘겨 **전체 교체**.

cron 표 5칸 의미:

```
* * * * *   command
│ │ │ │ │
│ │ │ │ └── 요일 (0~6, 0=일요일)
│ │ │ └──── 월   (1~12)
│ │ └────── 일   (1~31)
│ └──────── 시   (0~23)
└────────── 분   (0~59)
```

`* * * * *` = 매분, `10 3 * * *` = 매일 03 시 10 분.

#### 왜 명령줄 앞에 `AGENT_HOME=…` 을 다시 적나

cron 은 **로그인 셸이 아니다**. `.bashrc` 도 안 읽고, 환경변수도 거의 비어 있다[^9]. 그래서 `monitor.sh` 가 의존하는 `AGENT_HOME / AGENT_PORT / AGENT_LOG_DIR` 을 cron 줄 안에 직접 박아 넣어야 한다.

`A=1 B=2 command` 형태로 명령 앞에 변수를 두면 **그 한 명령에만** 적용된다[^10] (export 없이도).

## 4. 운영 3종 — 한 줄씩 해설

### 4.0 잠깐 — `grep` / `sed` / `awk` 3대장 미니 소개

monitor.sh / report.sh 를 읽으려면 이 셋이 어떤 역할인지 한 줄씩이라도 알아야 한다.

| 도구 | 한 줄로 |
|------|--------|
| **grep** | "**찾기**" — 패턴과 일치하는 줄만 골라낸다. `ls | grep .log` |
| **sed**  | "**바꾸기**" — 줄 단위로 검색해 다른 텍스트로 치환. `sed 's/old/new/'` |
| **awk**  | "**컬럼 다루기 + 계산**" — 공백 기준으로 줄을 컬럼(`$1 $2 $3 …`)으로 자르고, 합계·평균·필터를 표현. `awk '{print $2}'` |

기억법: **"찾으면 grep, 바꾸면 sed, 계산하면 awk"**.

#### awk 프로그램의 뼈대 한 번 보기

```bash
awk '패턴 { 액션 } 패턴 { 액션 } …'  파일
```

- **패턴이 참인 줄에 한해 액션 실행.** 패턴이 비어 있으면 **모든 줄** 실행.
- 자주 쓰는 패턴: `/정규식/`, `$3 > 100`, `BEGIN` (입력 전 1번), `END` (입력 후 1번).
- 액션 안에선 `$0`(줄 전체), `$1`(첫 컬럼), `$2`, … `NF`(컬럼 수), `NR`(줄 번호) 같은 내장 변수를 쓴다.

예:

```bash
ls -l /etc | awk '$5 > 1000 { print $9, $5 }'
#         ┬                     ┬       ┬
#         │                     │       └ 출력할 컬럼들
#         │                     └ 5번째 컬럼(크기) > 1000 인 줄만
#         └ ls -l 출력을 awk 에 흘려보냄
```

→ "1000바이트 이상인 파일의 이름·크기" 만 추려서 출력. 이게 awk 의 전형적 패턴이다.

> awk 가 따옴표(`'…'`) 안에 또 다른 작은 언어를 품고 있어서 처음엔 낯설다. **"awk 인용부호 안은 별도 언어다"** 라고 생각하면 마음 편하다.

### 4.1 `monitor.sh` — 시스템 상태 수집

monitor.sh 는 cron 으로 매분 호출되어 다음을 한다.

1. Health check (프로세스 살아 있나, 포트 LISTEN 하나) — 실패 시 `exit 1`
2. 방화벽 활성 여부 경고
3. CPU/MEM/DISK 수집
4. 임계값 초과 시 WARNING
5. `[시각] PID:… CPU:…% MEM:…% DISK_USED:…%` 한 줄을 `monitor.log` 에 append
6. 파일이 10MB 넘으면 `.1 … .10` 으로 로테이션

#### 변수 + 기본값 패턴

```bash
APP_NAME="${APP_NAME:-agent-app}"
APP_PORT="${AGENT_PORT:-15034}"
LOG_DIR="${AGENT_LOG_DIR:-/var/log/agent-app}"
```

- `${VAR:-default}` = "**VAR 이 비어 있거나 없으면 default 를 써라**".
- 덕분에 `APP_NAME=foo ./monitor.sh` 같은 1회성 override 가 가능. cron 에선 `AGENT_PORT=15034` 처럼 명령줄 앞 변수를 받아간다.

> 변수 정의 시 `=` 양옆에 **공백이 있으면 안 된다**. `NAME=foo` (O), `NAME = foo` (X — "NAME 명령어가 없다"고 해석됨).

#### 명령어 결과를 변수에 — `$(...)`

```bash
APP_PID="$(pgrep -x "${APP_NAME}" | head -n1 || true)"
```

- `$(명령)` = "명령을 실행한 결과(표준 출력)" 를 그 자리에 끼워 넣음 ("명령어 치환").
- `pgrep -x agent-app` : 프로세스 이름(`/proc/PID/comm`) 이 `agent-app` 와 **정확히 일치**하는 PID 만 출력[^11].
  - `-x` 대신 `-f` 도 있는데 (`-f` = cmdline 전체에서 매칭) 우리 경로엔 `agent-app` 이라는 글자가 **디렉토리 이름**(`/home/agent-admin/agent-app/...`)에도 들어있어, monitor.sh 가 **자기 자신을 매칭하는 사고**가 난다. → `-x` 가 안전.
- `| head -n1` : 여러 PID 가 잡혀도 첫 번째만.
- `|| true` : 일치 프로세스 없을 때(=실패) 도 OK 로 처리. `set -e` 환경이라면 여기서 죽지 않게 하는 가드.

#### 조건문 — `if [[ ... ]]; then ... fi`

```bash
if [[ -z "${APP_PID}" ]]; then
    echo "Checking process '${APP_NAME}'... [FAIL]"
    exit 1
fi
```

| 표현 | 의미 |
|------|------|
| `-z "$x"` | x 가 **빈 문자열** |
| `-n "$x"` | x 가 **비어있지 않음** |
| `"$a" = "$b"` | 문자열 동일 |
| `$a -gt $b` | **정수** 비교 (gt, lt, eq, ne, le, ge) |
| `-f path` / `-d path` | 파일 / 디렉토리 존재 |

`[ ]` 와 `[[ ]]` 둘 다 가능하지만 **`[[ ]]` 가 더 안전** (공백/특수문자 처리 우수, `&&`/`||` 도 안에서 사용 가능).

#### 포트 LISTEN 확인 — `ss` 와 폴백

```bash
if command -v ss >/dev/null 2>&1; then
    PORT_OK=$(ss -tlnH 2>/dev/null | awk -v p=":${APP_PORT}" '$4 ~ p {print "Y"; exit}')
else
    PORT_OK=$(netstat -tln 2>/dev/null | awk -v p=":${APP_PORT}" '$4 ~ p {print "Y"; exit}')
fi
```

- `command -v ss` : "ss 명령이 PATH 에 있는가" 만 확인. 출력은 필요 없으니 `>/dev/null 2>&1` 로 버림.
- `ss -tlnH` : TCP(`-t`) / LISTEN(`-l`) / 숫자(`-n`) / 헤더 없이(`-H`) 출력[^12]. 4번째 컬럼이 `Local Address:Port`.
- `awk -v p=":15034"` : awk 안에 변수 `p` 를 만들어 셸 값을 전달.
- `$4 ~ p` : 4번째 컬럼이 정규식 `p` 와 매칭되면 참.
- `{print "Y"; exit}` : 한 줄만 찾으면 Y 출력하고 즉시 종료.

> `ss` 가 없는 환경 대비 `netstat` 폴백을 둠 — 미니멀 컨테이너 이미지에선 둘 중 하나만 있을 수 있다.

#### 방화벽 상태 — 3단 폴백

```bash
if systemctl is-active --quiet ufw 2>/dev/null; then
    FIREWALL_OK="Y"
elif [ -r /etc/ufw/ufw.conf ] && grep -qE '^ENABLED=yes' /etc/ufw/ufw.conf 2>/dev/null; then
    FIREWALL_OK="Y"
elif systemctl is-active --quiet firewalld 2>/dev/null; then
    FIREWALL_OK="Y"
fi
```

monitor.sh 는 **agent-admin (sudo 없음)** 으로 cron 에서 돌기 때문에 `sudo ufw status` 같이 root 가 필요한 명령은 못 쓴다. 그래서 3중 fallback:

1. `systemctl is-active --quiet ufw` — 정석 (일반 사용자도 read-only 로 가능).
2. `/etc/ufw/ufw.conf` 의 `ENABLED=yes` — 이 파일은 기본 644 라 누구나 read. 일부 환경에서 룰은 적용됐는데 systemd unit 이 inactive 로 잡히는 경우의 보강.
3. `firewalld` (다른 배포판 대안) 도 같은 방식으로.

#### CPU 측정 — top 의 idle 컬럼 찾기

```bash
CPU_USAGE="$(top -bn1 | awk -F'[ ,]+' '/Cpu\(s\)/ {for(i=1;i<=NF;i++) if ($i ~ /id$/) {print 100 - $(i-1); exit}}')"
```

이게 가장 복잡한 한 줄이라 풀어 보자.

- `top -bn1` : top 을 batch(`-b`) 모드로 1회(`-n1`) 실행. 한 장면 스냅샷이 텍스트로 나옴.
- `awk -F'[ ,]+'` : 컬럼 구분자를 "공백 또는 쉼표 1 개 이상" 으로 재정의. top 출력은 두 가지가 섞여 있어 둘 다 쳐줘야 한다.
- `/Cpu\(s\)/ { ... }` : `Cpu(s)` 가 들어간 줄에만 액션 적용 (top 의 CPU 통계 줄).
- `for(i=1;i<=NF;i++)` : 모든 컬럼 순회. `NF` = Number of Fields.
- `if ($i ~ /id$/)` : 그 컬럼이 `id` 로 끝나면 (top 출력은 `... 99.5 id ...` 처럼 idle 값 옆에 `id` 라벨).
- `print 100 - $(i-1)` : 그 직전 컬럼(=idle 비율) 을 100 에서 뺌. **CPU 사용률 = 100 − idle**.
- `exit` : 찾자마자 종료. 효율.

#### 메모리 / 디스크 — 짧다

```bash
MEM_USAGE="$(free | awk '/^Mem:/ {printf "%.1f", $3/$2*100}')"
DISK_USED="$(df -P / | awk 'NR==2 {gsub("%","",$5); print $5}')"
```

- `free` 의 `^Mem:` 줄 → `$2` = total, `$3` = used → 사용률 = used/total × 100[^13].
- `df -P /` 의 2번째 줄 → 5번째 컬럼이 `23%` 같은 형태 → `gsub("%","",$5)` 로 % 제거.
- `printf "%.1f"` : 소수 1자리 출력.

#### 임계값 — bash 가 소수 계산이 안 된다

```bash
awk -v v="${CPU_USAGE}" -v t="${CPU_THRESHOLD}" 'BEGIN {exit !(v+0 > t+0)}' \
    && echo "[WARNING] CPU threshold exceeded (${CPU_USAGE}% > ${CPU_THRESHOLD}%)"
```

- bash 의 `[[ $a -gt $b ]]` 는 **정수만**[^14]. `25.3 > 20` 같은 소수 비교는 못 한다.
- 우회: awk 에서 비교 → 결과를 종료 코드로 → bash 의 `&&` 와 엮음.
- `v+0` : 문자열 `"25.3"` 에 0 을 더해 강제 숫자 변환.
- `BEGIN { ... }` : 입력 없이 한 번만 실행.
- `exit !(v > t)` : 참(1)이면 `!`로 0 → awk 종료 코드 0 (성공) → `&&` 다음 줄 실행.

이 패턴은 "**bash 에서 소수 비교가 필요할 때의 표준 트릭**" — 외워두면 평생 쓴다.

#### 로그 append + 로테이션

```bash
echo "${LOG_LINE}" >> "${LOG_FILE}"
```

- `>>` = **이어쓰기** (`>` 는 덮어쓰기). 매분 한 줄씩 쌓이므로 시계열 로그.

```bash
SIZE="$(stat -c %s "${LOG_FILE}" 2>/dev/null || wc -c < "${LOG_FILE}")"
if [[ "${SIZE}" -ge "${MAX_LOG_SIZE}" ]]; then
    rm -f "${LOG_FILE}.${MAX_LOG_FILES}"
    for ((i=MAX_LOG_FILES-1; i>=1; i--)); do
        [[ -f "${LOG_FILE}.${i}" ]] && mv "${LOG_FILE}.${i}" "${LOG_FILE}.$((i+1))"
    done
    mv "${LOG_FILE}" "${LOG_FILE}.1"
    : > "${LOG_FILE}"
fi
```

- `stat -c %s 파일` : 파일 크기(바이트). 일부 환경에 없을 수 있어 `wc -c < 파일` 폴백.
- `for ((i=...))` : C 스타일 for 반복. **bash 전용**, sh 에선 안 됨.
- 동작 순서:
  1. 가장 오래된 `.10` 삭제
  2. `.9 → .10`, `.8 → .9`, … `.1 → .2` 로 한 칸씩 밀기
  3. 현재 `monitor.log → monitor.log.1` 로 이름 변경
  4. `: > monitor.log` 로 0바이트 새 파일 생성 (`:` 는 "아무것도 안 함" 명령, 그 출력을 빈 파일로 리다이렉트).

### 4.2 `report.sh` — awk 한 덩어리 통계

monitor.log 의 각 줄에서 시각/CPU/MEM/DISK 를 뽑아 평균·최대·최소 + 시각을 같이 보고한다.

```bash
awk -v ts_start="${START_TS}" -v ts_end="${END_TS}" '
{
    if (match($0, /\[[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}\]/)) {
        ts = substr($0, RSTART+1, RLENGTH-2)
    } else { next }

    if (ts_start != "" && ts < ts_start) next
    if (ts_end   != "" && ts > ts_end)   next

    cpu = ""; mem = ""; disk = ""
    if (match($0, /CPU:[0-9.]+%/))       cpu  = substr($0, RSTART+4, RLENGTH-5)
    ...

    n++
    cpu_sum += cpu
    if (n == 1 || cpu+0 > cpu_max+0) { cpu_max = cpu; cpu_max_ts = ts }
    ...
}
END {
    printf "    Average : %.1f%%\n", cpu_sum/n
    ...
}
' "${LOG_FILE}"
```

#### awk 의 핵심 내장 변수 5 개

| 변수 | 의미 |
|------|------|
| `$0` | 줄 전체 |
| `$1`, `$2`, … | N 번째 컬럼 (공백으로 자름) |
| `NF` | 컬럼 개수 |
| `NR` | 현재 줄 번호 (1부터) |
| `FS` | 컬럼 구분자 (`-F` 옵션으로 바꿈) |

#### `match` + `substr` — 정규식으로 일부 추출

```awk
if (match($0, /CPU:[0-9.]+%/)) cpu = substr($0, RSTART+4, RLENGTH-5)
```

- `match(문자열, 정규식)` : 매칭되면 `RSTART`(시작 위치) 와 `RLENGTH`(매치 길이) 를 세팅, 매칭 안 되면 0.
- `substr(문자열, 시작, 길이)` : 부분 문자열. `RSTART+4` 로 `CPU:` 4 글자를 건너뛰고, `RLENGTH-5` 로 양 끝의 `CPU:` (4) + `%` (1) 를 빼서 숫자만.

#### `BEGIN` / `END` 패턴

| 패턴 | 언제 실행 |
|------|----------|
| `BEGIN { ... }` | 입력 읽기 **전**, 한 번 |
| `END   { ... }` | 입력 다 읽은 **뒤**, 한 번 |

→ "초기화" 와 "총합·평균 출력" 자리.

#### awk 변수명에 `END` 를 못 쓰는 함정

```bash
# 이전엔 -v END="${END_TS}" 였는데 mawk 에서 다음 에러:
#   awk: cannot command line assign to END
#   reserved for special use
awk -v ts_start="..." -v ts_end="..."     # 이 이름으로 바꿔야 안전
```

`END` 는 awk 의 예약 키워드라 일부 구현(특히 mawk)에선 `-v` 로 값을 줄 수 없다[^15]. **변수명에 BEGIN/END/NF/NR 같은 키워드는 피하자**.

#### `n == 1 || cpu+0 > cpu_max+0`

처음 줄에서는 `cpu_max` 가 비어 있으므로 무조건 갱신, 그 뒤로는 큰 값이 들어올 때만. **0 더하기 트릭 (`+0`)** 으로 강제 숫자 비교.

### 4.3 `archive_logs.sh` — find + 안전한 while 루프

```bash
while IFS= read -r -d '' f; do
    base="$(basename "${f}")"
    ts="$(date '+%Y%m%d_%H%M%S')"
    target="${ARCHIVE_DIR}/${base}.${ts}.gz"
    if gzip -c "${f}" > "${target}" 2>/dev/null; then
        rm -f "${f}"
        COMPRESSED=$((COMPRESSED + 1))
    fi
done < <(find "${SRC_DIR}" -maxdepth 1 -type f -name '*.log' -mtime +7 -print0 2>/dev/null)
```

낯설어 보이는 건 다 **공백/특수문자가 든 파일명에서도 안전하게 동작하기 위한 관용구**.

#### `find` 옵션

- `-maxdepth 1` : 하위 디렉토리까지 내려가지 말고 그 폴더 안만.
- `-type f` : 일반 파일만 (디렉토리/심볼릭 링크 제외).
- `-name '*.log'` : `.log` 로 끝나는 이름.
- `-mtime +7` : 마지막 수정으로부터 **7일 초과** 지난 것 (`-mtime -7` 은 7일 이내)[^16].
- `-print0` : 파일명 사이를 **널 문자 `\0`** 로 구분. 줄바꿈 구분이면 이름에 줄바꿈이 든 파일에 깨짐[^17].

#### `while IFS= read -r -d '' f; do ... done < <(...)`

| 토큰 | 역할 |
|------|------|
| `IFS=` | 단어 구분자 비움 → 공백 보존 |
| `read -r` | 백슬래시 이스케이프 처리 안 함 (raw) |
| `read -d ''` | 입력 구분자를 널 문자로 (find 의 `-print0` 와 짝) |
| `< <(cmd)` | "프로세스 치환" — 명령 출력을 파일처럼 read 가 받아 읽음 |

이 패턴 = "**파일 목록을 안전하게 한 줄씩 처리할 때의 정석**". 외워두면 일생 쓴다.

#### gzip + 원본 삭제

```bash
if gzip -c "${f}" > "${target}" 2>/dev/null; then
    rm -f "${f}"
fi
```

- `gzip -c` : 원본을 지우지 않고 압축 결과를 stdout 으로.
- `> target` : 그 출력을 `.gz` 새 파일로 저장.
- **압축이 성공해야 원본 삭제** — `&&` 가 아니라 `if` 로 분기한 이유는, `set -u` 만 켜진 상황에서도 명확히 "둘 다 성공해야 다음" 을 표현하기 위해.

## 5. `00_run_all.sh` — wrapper 의 작은 트릭

```bash
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
export SOURCE_DIR="${SOURCE_DIR:-$HERE}"

STEPS=(
    "01_ssh_hardening.sh"
    "02_firewall_allowlist.sh"
    ...
)

TOTAL="${#STEPS[@]}"
for step in "${STEPS[@]}"; do
    bash "${HERE}/${step}"
done
```

- `BASH_SOURCE[0]` : 지금 실행 중인 스크립트 파일의 경로. `$0` 도 비슷하지만 source 됐을 땐 호출 측 셸 이름이 잡혀 위험.
- `$(cd "$(dirname …)" && pwd)` : 상대 경로를 절대 경로로 만들기 위한 관용구. `dirname` 으로 부모 디렉토리, `cd` + `pwd` 로 절대화.
- `STEPS=( "..." "..." )` : 배열. **bash 전용** (sh 에는 배열 없음).
- `"${#STEPS[@]}"` : 배열 길이. `#` 는 "개수", `[@]` 는 "모든 원소".
- `"${STEPS[@]}"` : 모든 원소를 각각의 인자로 전개 (vs `"${STEPS[*]}"` 는 한 문자열로 합침).

## 5.5 정규식 — 최소 생존 키트

문서 곳곳에 `^#?Port`, `[0-9.]+%`, `/Cpu\(s\)/` 같은 패턴이 나왔다. 이건 모두 **정규식(regular expression)** 이다. "문자열의 패턴" 을 표현하는 작은 언어로, grep / sed / awk 의 핵심 무기.

가장 자주 쓰는 메타문자 10개만 외워도 80% 가 읽힌다.

| 문자 | 의미 | 예 |
|------|------|----|
| `.` | **아무 글자 한 개** | `a.c` → `abc`, `a c`, `a9c` |
| `*` | **앞 글자 0회 이상** | `ab*` → `a`, `ab`, `abbb` |
| `+` | **앞 글자 1회 이상** (확장 정규식) | `ab+` → `ab`, `abbb` (`a` 는 X) |
| `?` | **앞 글자 0회 또는 1회** | `colou?r` → `color`, `colour` |
| `^` | **줄의 시작** | `^Port` → "Port 로 시작하는 줄" |
| `$` | **줄의 끝** | `\.log$` → ".log 로 끝나는 줄" |
| `[abc]` | **괄호 안 글자 중 하나** | `[0-9]` → 숫자 한 개 |
| `[^abc]` | **괄호 안 글자가 아닌** 한 개 | `[^0-9]` → 숫자 아닌 한 개 |
| `\` | **다음 글자를 메타가 아닌 그냥 글자로** | `\.` → 진짜 점, `\(` → 진짜 괄호 |
| `()` | 묶음 (확장 정규식에서 그룹) | `(abc)+` → abc 가 한 번 이상 |

다시 우리 코드의 패턴을 풀어 보면:

- `^#?Port .*` → 줄 시작(`^`)에 `#` 이 **있어도 없어도(`?`)** 좋고, 그 뒤 `Port `, 그 뒤 아무 글자 0개 이상(`.*`). → 주석 처리된 `#Port 22` 와 그냥 `Port 22` 를 둘 다 잡으려는 트릭.
- `[0-9.]+%` → 숫자 또는 점이 1개 이상 + `%`. → `25.3%`, `100%` 같은 패턴.
- `/Cpu\(s\)/` → 문자 그대로 `Cpu(s)`. 괄호는 메타이므로 `\(`, `\)` 로 **이스케이프**.
- `\.log$` → 글자 그대로 `.log` 로 끝남. `.` 앞에 `\` 안 붙이면 "아무 글자 + log" 가 돼 버려 의도와 달라진다.

> 정규식엔 **BRE(기본)** 과 **ERE(확장)** 두 종류가 있다. `+`, `?`, `|`, `()` 가 메타로 쓰이려면 ERE 가 필요. `grep -E`, `sed -E`, `awk` (기본 ERE) 가 ERE 모드.

## 6. 자주 헷갈리는 포인트 모음

1. **`=` 양옆 공백 금지** — `A=1` (O), `A = 1` (X: "A 라는 명령어가 없다" 에러).
2. **변수는 무조건 큰따옴표로 감싸기** — `"${VAR}"`. 공백/특수문자 든 경로에서 안 그러면 단어가 쪼개진다.
3. **작은따옴표 vs 큰따옴표**
   - `'...'` : 안의 모든 것을 문자 그대로. `$VAR` 도 안 풀림.
   - `"..."` : `$VAR` 를 값으로 치환.
   - 우리 heredoc 에서 `<<'EOF'` 처럼 마커를 작은따옴표로 감싸는 이유가 이것.
4. **숫자 비교 vs 문자열 비교**
   - 숫자(정수): `$a -gt $b`
   - 문자열: `"$a" = "$b"`
   - 소수: bash 불가 → awk 위임 (§4.1 임계값 트릭)
5. **백틱 `` `…` `` 보다 `$(…)`** — 가독성·중첩 모두 우월.
6. **종료 코드 0 = 성공**. 사람 직관과 반대라 처음에 헷갈린다. cron/CI 가 이 숫자를 본다.
7. **`if` 의 조건은 명령의 종료 코드를 본다** — `if grep -q foo file; then …` 는 grep 이 찾으면 0 → 참.
8. **줄바꿈은 LF** — Windows 에서 만든 파일은 CRLF, bash 가 `\r` 까지 명령 일부로 인식해 깨진다 → `dos2unix` (06 단계가 자동으로 처리해 줌).
9. **`sudo` 와 리다이렉트** — `sudo cmd > file` 의 `> file` 은 sudo 가 아닌 **호출 측 셸** 이 처리한다. 권한이 모자라면 거부. 해결: `cmd | sudo tee file > /dev/null` 또는 `sudo bash -c 'cmd > file'`.
10. **`pgrep -f` vs `-x` 자기참조 함정** — cmdline 에 자기 경로가 들어가면 자신을 매칭하는 사고. 우리 `monitor.sh` 가 `-x` 를 쓰는 이유.

## 7. 직접 실험해 보기 좋은 작은 예제

```bash
# 1) 변수와 기본값 + 첫 번째 인자
NAME="${1:-friend}"

```

```bash
# 2) 조건문 + 파일 검사
if [[ -f /etc/hosts ]]; then

    echo "missing"
fi
```

```bash
# 3) 반복문 — 배열 순회
FRUITS=("apple" "banana" "cherry")
for f in "${FRUITS[@]}"; do
    echo "fruit: $f"
done
```

```bash
# 4) 명령어 결과 + 숫자 조건
COUNT="$(ls /etc | wc -l)"
```
